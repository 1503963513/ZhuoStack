# 模板定制指南

本文说明如何将 ZhuoStack 调整为自己的项目。部署方式见[部署指南](deployment.md)；新增完整业务模块时，参考[新增业务模块示例](module-development.md)。

## 建议的定制顺序

1. 先按 [README 快速开始](../README.md#快速开始) 启动本地环境，确认 API、Web、数据库和 Redis 均正常。
2. 修改产品名称、Logo、版权信息和默认外观。
3. 决定保留哪些演示账号、菜单和管理模块。
4. 增加业务数据模型和功能模块，再配置菜单、按钮权限及前端文案。
5. 按目标数据库部署并验证迁移，最后检查生产环境配置和管理员账号。

## 品牌与系统参数

可在后台“系统参数设置”中修改已提供的系统名称、版权声明、默认主题、注册开关、验证码开关和新建用户初始密码等参数。参数按代码中登记的配置项生效；它不是任意环境变量管理器。

Logo、登录页视觉或默认文案若没有对应系统参数，应在前端相应页面或共享布局组件中调整。中英文文案维护在 `apps/web/src/locales/zh-CN/` 与 `apps/web/src/locales/en-US/`。新增菜单路径时要同步两种语言的 `menu` 标题映射。

部署地址、数据库、Redis、JWT 密钥、对象存储等运行环境值由 API/Web 环境文件配置，不能放入前端公开配置或提交真实凭据。配置项以 `apps/api/.env.example`、`apps/web/.env.example` 及部署文档为准。

## 演示数据与菜单

`apps/api/prisma/seed.ts` 包含演示用户、角色、菜单及权限数据。开发环境可以按项目脚本填充演示数据；普通 seed 会清空并重建部分数据，只能用于空库或可丢弃的非生产数据库。生产环境不要运行 `pnpm db:seed`，部署时保持 `DB_SEED_ON_START=false`。生产首管初始化使用独立的 `pnpm admin:bootstrap`，限制和步骤见下文。

定制菜单和初始权限时，检查 `seed.ts` 中的菜单树、按钮权限和角色关联。运行 seed 只适用于开发/测试初始化；线上新增菜单权限应通过后台菜单与角色管理，或通过经过审核的专用数据迁移完成，避免重新 seed 覆盖真实数据。

如果项目不需要某个内置模块，先检查其他模块是否依赖它，再同步调整 API 的 `AppModule`、系统模块 imports、前端路由、种子菜单、权限和相关文案。仅隐藏菜单不会禁用后端路由，也不构成接口访问控制；后端仍须保留认证和权限检查。

## 生产管理员初始化

仓库中记录的 `admin@example.com / Admin@123456` 和普通测试用户密码仅供本地演示。正式环境不要使用演示账号，不要开启生产 seed。新建用户默认密码可在参数设置中配置。上线后限制管理端网络访问，并使用唯一强密码。

全新生产数据库完成迁移后，使用 `pnpm admin:bootstrap` 创建首个超级管理员和默认管理菜单。该命令只在 `NODE_ENV=production` 下执行，要求显式确认和独立管理员凭据；检测到用户、菜单、角色、字典、部门或岗位记录时会拒绝运行。它不清空数据库、不创建普通演示用户，也不创建示例部门或岗位；生产管理员初始不关联部门和岗位，可按实际组织架构在后台配置。初始化凭据应通过受控环境变量临时提供，执行后立即从环境或密钥注入配置中移除；不要写入仓库、镜像或应用日志。此操作只执行一次，不用于已有环境的账号提权或重置。

## 新增模块前的检查

- 明确模块归属、菜单路径和所需按钮权限。
- 确认新增数据是否需要 PostgreSQL 与 MySQL 同时支持。
- 先定义后端 DTO 和响应，再生成 OpenAPI/Orval 客户端；不要直接改 `apps/web/src/api/generated/`。
- 需要 Redis 缓存时，为新键选择明确前缀并登记到监控模块的允许/保护前缀清单。
- 新增页面、菜单或按钮后同步中英文文案，并检查角色授权。
- 为影响数据或权限的行为保留必要的操作日志和错误处理。

详细文件结构和命令见[新增业务模块示例](module-development.md)。
